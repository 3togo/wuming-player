# 多語片名搜尋

搜尋的目標不是翻譯一般句子，而是找出同一影視作品在不同語言及地區使用的正式片名。
因此，英文片名不能只做字面翻譯，繁體與簡體片名也必須視為相同文字系統的等價形式。

## 使用者行為

搜尋只在以下操作後送出：

- 按下輸入法的搜尋／完成動作
- 點選熱門建議
- 點選搜尋建議
- 點選搜尋歷史

輸入框的文字變更只會更新建議，不會自動開始多站點搜尋。

搜尋頁與搜尋結果頁都提供嚴格搜尋切換鈕。設定會持久保存；在結果頁切換時，應用會
取消進行中的工作、清除舊結果，再以同一關鍵字重新搜尋。

## 查詢規劃

`SearchQueryPlanner` 依序建立最多三個去重後的變體：

1. 使用者輸入的原始片名
2. 繁體中文轉換後的簡體片名
3. 已知或查找到的正式簡體中文別名

沒有必要的變體不會加入。例如原始輸入已是簡體中文時，不會重複送出相同查詢。

| 輸入 | 可能的查詢 |
| --- | --- |
| `風月俏佳人` | `風月俏佳人`、`风月俏佳人` |
| `Pretty Woman` | `Pretty Woman`、`风月俏佳人`、其他已知地區別名 |
| `三體` | `三體`、`三体` |

英文別名解析依序使用：

1. 內建的高可信片名資料
2. 本機已保存的成功解析
3. 豆瓣片名建議
4. Wikidata 的影視類實體與中文標籤

網路解析有時間上限。解析失敗時保留原始英文搜尋，不會阻止搜尋，也不會以一般機器
翻譯產生可能錯誤的片名。

## 正規化與作品識別

`TitleNormalizer` 統一處理：

- Unicode NFKC 正規化
- 不依賴裝置語系的小寫轉換
- 標點與多餘空白
- 繁簡中文比較
- 中英文混合片名的有效片段

已解析的片名會形成 `TitleIdentity`，包含 canonical ID、別名、年份及作品類型。搜尋
結果會記錄原始查詢、實際命中的查詢及可信別名，供合併、排序、標示及嚴格篩選共用。

## 寬鬆與嚴格模式

寬鬆模式保留 Provider 回傳的結果，再依作品識別與相關性排序，適合來源的搜尋能力較
弱或片名包含附加資訊的情況。

嚴格模式只保留下列強命中：

- 正規化後的片名完全相同
- 片名以查詢開頭，後方只有年份、季數等獨立後綴
- 查詢以結果片名開頭
- 結果命中同一作品的可信別名

嚴格篩選在共用結果管線執行，因此適用於手機與 TV、一般搜尋與快速搜尋。兩種模式的
快取鍵不同，不能重用另一模式的結果。

## 維護片名別名

內建別名位於：

```text
app/src/main/java/com/wuming/android/tv/search/TitleAliasRepository.kt
```

新增資料時應：

1. 使用穩定的 canonical ID，例如 Wikidata 或豆瓣 ID。
2. 收錄英文原名、簡體正式片名及必要的地區別名。
3. 不加入推測性的逐字翻譯。
4. 補充 `TitleAliasRepositoryTest` 與查詢規劃測試。
5. 執行 `./gradlew testKeyLogic` 及 `./gradlew assembleDebug`。

## 主要實作

| 類別 | 職責 |
| --- | --- |
| `SearchQueryPlanner` | 建立有上限、去重後的查詢變體 |
| `TitleAliasRepository` | 解析、保存及提供正式片名別名 |
| `TitleNormalizer` | 跨語系正規化與繁簡等價比較 |
| `SearchResultAnnotator` | 標記作品身份及執行嚴格篩選 |
| `SearchResultMerger` | 合併重複作品並保留最佳結果 |
| `SiteViewModel`／`VodBrowse` | 在共用搜尋管線套用規劃與模式 |

相關回歸測試位於 `app/src/test/java/com/wuming/android/tv/search/`。
