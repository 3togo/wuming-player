## REF-004 completed: shared MacCMS collection fallback

Winbox retries the legacy `ac=videolist` action when search or detail returns no items.
TV already used that fallback for categories, but search returned empty and detail threw
without trying the alternate action. This prevented complete navigation of legacy JSON APIs.

Added one private collection-request abstraction to the existing maccms-core executor.
Category, search and detail now share a bounded fallback policy. Query, ID, page, filter,
extension and transport headers retain their existing paths; only `ac` changes on retry.
XML already requests videolist and is not retried. Transport and malformed-payload errors
are propagated. Empty detail after the retry remains an error.

Detail checks the raw empty list, not decoded search items: legitimate detail responses
can omit vod_id and rely on the requested ID. This prevents an unnecessary second request
or loss of valid detail information. No C# source was copied and no new dependency added.
